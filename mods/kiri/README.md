# 키리 확장 모드

환세기담의 키리를 플레이어로 쓰는 팬 메이드 확장이다. 본체(`src/`)는 키리를 모르고, 개발 서버에서만 이 폴더를 불러온다. 확장 모드 구조는 저장소 루트 `EXTENSION.md`에 있다. 이 문서의 경로는 따로 적지 않으면 `mods/kiri/` 기준이다.

## 폴더

- `src/`: 게임에 들어가는 코드. `index.ts`(진입점: 그림 읽기, 시트·캐릭터 등록, `?char=kiri`), `kiri.ts`(`CharDef` 스키마와 키리 표 생성, 본체 `characters.ts`에 등록), `hitboxDef.ts`(판정 값, 판정 편집기가 다시 씀).
- `dev/`: 브라우저 개발 도구. `index.ts`(개발용 주소 인자 처리, `src/index.ts`가 그런 인자가 있을 때만 불러옴), `hitbox.ts`(판정 표시), `sprites.ts`·`editor.ts`(미리보기·판정 편집기), `sheetEditor.ts`·`sheetCheck.ts`(시트 에디터·시트 검사).
- `art/`: 브라우저·Node 공용 그림 로직. `sheets.ts`(작업 시트 배치), `walkFromStand.ts`(걷기 합성), `hairLag.ts`(머리카락 휘기).
- `tools/`: Node 코드. `export.ts`(작업 파일 → 최종 그림), `png.ts`(PNG 읽기·쓰기), `serve.ts`(개발 서버 확장: 작업 파일 감시·내보내기, `PUT /dev/kiri-def`, `/dev/export`, 작업 시트 저장).
- `assets/`: 게임이 읽는 최종 그림 `KIRI.png`·`KIRI_FACE.png`(내보내기 결과).
- `work/`: 사용자가 그리는 작업 파일.

## 주소 인자(개발 서버에서만)

- `?char=kiri`: 키리로 시작. `?hitbox=1`: 판정 표시(스마슈에도 쓸 수 있음).
- `?sprites=kiri`·`?sprites=smash`: 스프라이트 미리보기. `?edit=kiri`: 판정 편집기. `?sheet=kiri`: 시트 에디터(게임 대신 뜸).

## 플레이(GAME START+)

환세기담의 키리(고용 경호원)를 플레이어로 쓸 수 있게 한다.

- 흐름: 1회차 클리어 → 전체 클리어 화면(장면 0xE)의 패스워드 → 타이틀 메뉴 `GAME START+` → 패스워드 입력 → 검증 통과 시 키리로, 기존보다 조금 어려운 규칙의 본편 시작.
- 공개: 지금은 개발 서버에서만 불러오고 배포 빌드(`npm run build`)에는 들어가지 않아, 작업 중 커밋을 푸시해도 배포 사이트는 스마슈 게임 그대로다. `GAME START+`가 완성되면 배포에 넣는 방법을 정한다.
- 캐릭터 선택 화면은 두지 않는다. 키리는 `GAME START+`로만 쓴다.
- 패스워드는 전체 클리어 화면의 것을 쓴다(플레이 시간으로 정해지고 5번째가 검산 글자라, 입력값을 00:00~99:59 전체와 대조해 검증할 수 있다). 방 4의 `PASSWORD`는 무작위 글자가 섞여 쓰지 않는다.
- 키리가 적용되는 곳은 게임 플레이와 게임 오버뿐이다. 타이틀 데모, 엔딩, 후일담, 스태프롤은 스마슈 그대로다(대사 147도 그대로).
- 공격 판정은 스마슈와 반드시 다르게 한다. 판정이 바뀌면 잔상 칸(13·16·19·22)도 그 궤적에 맞춰 그린다.
- 그림(사용자): `assets/KIRI.png`(`SMASH.png`와 같은 640×272 칸 배치, 캐릭터 칸만 키리로, 16색·인덱스 0 투명), `assets/KIRI_FACE.png`(128×128, 16색), `TITLE_P` kr·jp의 `GAME START+` 글자. 앞의 두 파일은 최종 파일이고, 그림은 `work/`의 작업 파일에 그린다(아래 "작업 파일과 내보내기").

- 판정 표시: `?hitbox=1`이면 `dev/hitbox.ts`가 `G.debug` 훅으로 장면 0에서 마지막 공격·스매시 판정 사각형(빨강, 10프레임 유지), 블록 타격점 7개(파랑), 충돌 중심(노랑)을 그린다.
- `SMASH.png` 칸 분류(사각형 92칸): 키리로 다시 그릴 캐릭터 칸은 0~32(걷기·공격·잔상 13·16·19·22·스매시 24~31·피격 32), 34(무덤 장면의 석상), 36(쓰러짐), 83~90이다. 33·37·38은 83·86·34와 같은 위치를 가리키는 칸이라 따로 그릴 것이 없다. 35(GAME OVER 글자), 39~82(칩·반짝임·파편·연기·무적 고리·벌레 모드 벌레), 91(표지)은 공용 칸이라 그대로 둔다. 51~58·64~82 일부는 코드에서 직접 참조를 찾지 못했지만 계산된 번호로 쓰일 수 있어 공용으로 둔다.
- 키리 시트는 표면 8·팔레트 0xE0 구간, 초상화는 표면 0x12·팔레트 0xF0 구간(원본 시트가 쓰지 않는 구간)에 따로 올린다. 그래서 키리는 16색을 자유롭게 정할 수 있고, 공용 이펙트는 계속 스마슈 시트(표면 5)에서 그려지므로 `KIRI.png`의 공용 칸은 쓰이지 않는다. 그림 파일의 팔레트는 앞 16색만 읽는다.
- 원본 HUD 초상화는 배경 `MAIN_BG` 오른쪽 위 4×4칸이 `MAP_DT_3`(640×32 띠)의 타일 4~19를 쓰는 것이다. 키리일 때는 그 위에 `KIRI_FACE.png`를 (512,0)px에 덮어 그린다.
- `KIRI.png`·`KIRI_FACE.png`는 있으면 읽고, 없으면 키리 시트는 `SMASH.png`로 대신하고 초상화는 덮지 않는다. PNG 해독기는 1·2·4·8비트 인덱스 컬러를 모두 읽는다(그림 도구가 16색을 4비트로 저장해도 된다). 인덱스 컬러가 아닌 파일(RGB 등)은 없는 것으로 치고 게임은 그대로 뜨며, 미리보기 시트 검사에 읽기 실패 경고가 뜬다. 자동 새로고침 중에 읽기에 실패하면 직전 그림을 유지한다. `?char=kiri`로 키리로 시작한다(개발 서버에서만).
- 키리 판정(충격파, 초기값): 무기는 전기 기타(환세기담 설정, 연주하면 충격파). 사거리는 짧고 몸을 중심으로 모든 방향을 덮는다. 휘두르기 판정은 네 방향 모두 같은 모양으로 몸 중심 기준 가로 막대(±40×±20)·세로 막대(±20×±40)·정사각형(±32)을 합친 팔각형(반경 약 40px, 스마슈는 앞쪽 80px). 시작 판정은 몸 둘레 ±24. 블록 타격점은 상하좌우 32px와 대각선(±24,±24) 8곳(스마슈 7곳, 타격점 수는 표 길이로 캐릭터마다 정한다). 스매시 판정은 스마슈와 같다.
- 키리의 잔상 칸(13·16·19·22, 80×80)은 포즈 오프셋을 (-16,-16)으로 바꿔 몸 중심이 칸 한가운데(40,40)에 오게 했다. 판정 사각형은 몸 중심 기준 값(`src/hitboxDef.ts`)에서 이 오프셋과 직전 포즈 오프셋으로 환산하므로(`src/kiri.ts`의 `kiriTables`) 잔상 위치를 바꿔도 판정은 몸 기준 그대로다.
- 그림 확인 도구(개발 서버에서만 열림): `?sprites=kiri`(또는 `smash`)는 게임 대신 스프라이트 미리보기를 띄운다. 걷기·공격·스매시 네 방향을 실제 애니 표와 포즈 오프셋으로 반복 재생하고(스페이스 정지, ←/→ 한 프레임), 공격 시작(f44==2)·휘두르기(f44==3) 판정, 블록 타격점, 스매시 판정, 몸 중심을 겹쳐 그린다. 피격·쓰러짐·무덤 석상은 정지 화면으로 보인다. `?sprites=smash`는 게임이 그림을 놓는 방식을 설명 표시와 함께 보여 준다(청록 상자 = 셀이 실제로 그려지는 위치와 크기, 보라 점 = 오프셋의 기준 `f38,f3c`, 노랑 점 = 몸 중심 `f38+24`, 패널 아래 글자 = 셀 크기·오프셋·셀 안의 몸 중심 좌표). 스마슈 잔상 칸(80×80) 안의 몸 위치는 방향마다 다르다(위 24,56 · 오른쪽 24,24 · 아래 56,24 · 왼쪽 56,56). 키리는 이와 달리 잔상 칸 오프셋을 (-16,-16)으로 두어 몸이 칸 한가운데(40,40)에 오게 했으며, 이것은 원본 방식이 아니라 키리의 선택이다. 오른쪽 아래에 시트 검사 결과(크기, 16번 이상 색 인덱스, 빈 캐릭터 칸, 원본 `SMASH.png`에 없던 칸 밖 픽셀, 초상화 크기)를 띄운다. `assets/KIRI.png`·`KIRI_FACE.png`가 바뀌면 1초 안에 새로고침 없이 반영된다(개발 서버가 `/dev/stat`으로 수정 시각을 알려 준다).
- 판정 편집기: `?edit=kiri`(미리보기에서 E 키로 전환). 키리의 판정(몸 중심 기준 px, 스키마는 `src/kiri.ts`의 `CharDef`)을 편집하고 Ctrl+S로 저장한다. 판정은 코드 파일 `src/hitboxDef.ts`의 `KIRI_DEF`이고, 저장하면 개발 서버(`PUT /dev/kiri-def`, 루프백 접속만 허용)가 이 파일 전체를 새로 쓴다(`npm run dev`의 `tsc --watch`가 다시 컴파일한다). 편집 중인 값은 이미 화면에 반영되어 있으므로 저장 후 새로고침할 필요는 없고, 파일을 밖에서 바꿨을 때만 새로고침한다. 단계 세 가지(Q): 휘두르기(사각형 3개와 블록 타격점, 잔상 칸 오프셋), 시작(사각형 1개), 피격 영역(적이 플레이어를 맞히는 영역, 기본은 점). 마우스로 사각형을 끌어 이동·모서리 조절, 방향키로 1px(Shift 4px) 이동, Alt+방향키로 크기, A·Delete로 타격점 추가·삭제, 우클릭 드래그로 잔상 위치 이동, C로 네 방향에 복사, M으로 반대 방향에 반전 복사, R로 방향 기본값, G로 스마슈 그림·판정 겹쳐 보기, Ctrl+Z로 되돌리기. 저장 전에는 패널에 미저장 표시가 뜬다.
- 그리기 가이드(저장소 밖 작업 파일): 640×272 투명 레이어에 캐릭터 칸(초록)·공용 칸(빨강) 테두리와 칸마다 키리 포즈 오프셋 기준 몸 중심(노랑 +)을 표시한 것, 칸 번호를 넣은 것, 128×128 초상화 자리에 스마슈 초상화를 35%로 깐 것.
- 초상화(`KIRI_FACE.png`): 사용자가 키리 원본 도트 그림(80×80, 35색, 15비트 색)을 바탕으로 직접 만든 128×128 그림이다. 회색·흰색 액자 안을 그림이 가득 채워 파란 배경은 없다. 팔레트 0xF0 구간은 이 파일만 쓰므로 액자 색까지 포함해 16색을 자유롭게 정한다. 색 번호는 0 검정 다음 많이 쓰인 순서다(0,0,0 · 90,41,0 · 255,231,206 · 165,82,33 · 255,255,255 · 206,99,33 · 255,181,107 · 255,189,16 · 187,187,187 · 239,140,66 · 255,206,156 · 165,165,165 · 189,82,173 · 222,0,0 · 0,140,33 · 119,119,119).
- 정할 것: 암호를 한 번 입력하면 기억할지 매번 입력할지, `+` 규칙의 구체 내용.

## 그림 작업(스마슈 틀)

키리는 스마슈와 같은 그림체(공 모양 머리에 손·발이 붙은 2등신)이고 걷기 칸의 동작도 스마슈와 같다. 방향마다 정지 칸 하나를 사용자가 스마슈 정지 칸 위에 손으로 그리고(기준 칸), 같은 방향의 걷기 칸은 그 기준 칸과 스마슈 걷기 칸을 합쳐 자동으로 만든 뒤, 작업 시트에 넣어 손으로 다듬는다.

- 작업 파일과 내보내기: 그림은 `work/`의 작업 시트(칸 크기별 네 장)와 `KIRI_FACE.png`(128×128)에 그린다. 작업 시트는 칸 크기가 같은 칸끼리 모은 격자이고, 한 줄이 한 동작이다(배치는 `art/sheets.ts`의 `KIRI_SHEETS`, 방향 순서는 위·오른쪽·아래·왼쪽). `KIRI_48x48.png`(240×576): 걷기 위·오른쪽·아래·왼쪽(정지·걷기1~4, 칸 0·1·2·83·84 / 3·4·5·85·86 / 6·7·8·87·88 / 9·10·11·89·90), 공격 몸(12·15·18·21), 피격·쓰러짐·석상(32·36·34). `KIRI_80x80.png`(320×160): 공격 잔상(13·16·19·22). `KIRI_48x80.png`(144×320): 위·아래의 공격 끝·스매시 두 칸(14·24·25 / 20·28·29). `KIRI_80x48.png`(240×192): 오른쪽·왼쪽의 공격 끝·스매시 두 칸(17·26·27 / 23·30·31). 각 시트는 위쪽 절반이 키리, 바로 아래 절반(빈 줄 없음)이 같은 배치의 참고용 스마슈 원본(0번 색은 투명)이고, 키리 16색과 스마슈 15색을 합친 31색 인덱스 PNG(0번 투명)로 저장해 두었다. 칸은 게임 칸을 그대로 옮긴 것이라 같은 동작의 칸끼리는 몸 중심이 같은 자리에 있어, Aseprite에서 Import Sprite Sheet(칸 크기 격자)로 프레임을 나누면 어니언 스킨으로 겹쳐 볼 수 있다. 저장할 때는 같은 배치(가로 칸 수 그대로)로 내보낸다. 작업 파일은 투명 배경 PNG면 형식은 자유다(Aseprite·Photoshop의 RGBA PNG나 투명 인덱스 PNG, `tools/png.ts`가 읽음). `tools/export.ts`가 작업 파일을 최종 16색 인덱스 PNG로 내보낸다. 키리 시트는 네 장의 위쪽 절반을 게임 배치(640×272)로 모은 뒤, 위치표가 있는 방향의 걷기 칸 중 비어 있는 칸만 합성하고(아래 "합성"), 오른쪽을 좌우로 뒤집어 비어 있는 왼쪽 칸을 채워 `assets/KIRI.png`로 쓴다. `KIRI_FACE.png`는 `assets/KIRI_FACE.png`로 그대로 쓴다. 그림이 있는 칸은 그대로 쓰므로, 합성 결과를 다듬으려면 그 칸을 시트에 넣고 고친다(지우면 다시 자동으로 채워짐). `KIRI.png`는 투명(알파 128 미만)과 최종 팔레트 0번 색을 인덱스 0으로 쓰고, 나머지 색은 최종 팔레트에서 같은 색의 번호를 쓴다. 팔레트에 없는 색은 쓰이지 않는 팔레트 칸에 들어가고, 칸이 모자라면 가장 가까운 색으로 바뀌며 그 수를 알린다. 시트의 아래 절반(스마슈 참고)은 읽지 않는다. 시트 폭이 배치와 다르거나 높이가 모자라면 내보내지 않는다. `npm run dev`가 켜져 있으면 개발 서버가 작업 파일을 0.5초마다 감시해 어느 하나가 저장될 때마다 내보낸다(시작할 때는 작업 파일이 최종 파일보다 새로우면 한 번 내보냄). 서버는 시작할 때 코드를 읽으므로 `tools/`·`art/`의 합성·배치 코드가 바뀌면 다시 켜야 한다. 서버 없이는 `node mods/kiri/tools/export.ts`로 내보낸다. 최종 파일을 직접 고치면 다음 내보내기 때 덮어써진다.
- 시트 에디터 `?sheet=kiri`(개발 서버에서만): 그리기 도구가 아니라 확인·위치 조정용이다. 위쪽에 네 작업 시트를 게임 배치로 모아 2배로 투명 바둑판 위에 보여 주고, 칸 테두리(캐릭터 칸 초록, 공용 칸 회색)·칸 번호·몸 중심(노랑 +, `24 − 포즈 오프셋`)을 겹쳐 그린다. 비어 있어 자동으로 채워지는 걷기 칸은 번호 옆에 "자동"을 붙이고 최종 파일의 그 칸을 반투명으로 보여 준다. 칸을 가리키거나 클릭하면 번호·이름(예: "7번 · 아래 걷기1", 공용 칸은 "공용", 자동 칸은 "비어 있어 자동으로 채움")·크기·작업 시트 위치(예: "KIRI_48x48.png 3줄 1번째")가 나온다. 아래에는 드롭다운에서 고른 동작(걷기·공격·스매시 × 위·오른쪽·아래·왼쪽, 피격·쓰러짐·무덤 석상)을 애니 표와 실제 포즈 오프셋으로 키리(편집 중인 그림, 자동 칸은 최종 파일)와 스마슈를 나란히 3배로 재생한다(160ms 간격, 피격·쓰러짐·석상은 정지 그림). 칸을 클릭하면 드롭다운도 그 칸이 속한 동작으로 바뀐다. 방향키로 선택한 칸의 그림을 칸 안에서 1px(Shift 4px) 옮긴다(칸 밖으로 나가는 픽셀이 생기거나 비어 있는 자동 칸이면 옮기지 않음). O는 스마슈 시트 35% 겹쳐 보기, C는 몸 중심 표시, Space는 애니메이션 정지, Ctrl+Z는 되돌리기, Ctrl+S는 저장이다. 저장하면 게임 배치를 다시 네 시트의 위쪽 절반으로 나눠, 바뀐 시트만 아래쪽 스마슈 참고까지 파일 전체를 RGBA PNG로 쓰고(`PUT /dev/mods/kiri/work/KIRI_48x48.png` 등, 루프백만) 곧바로 최종 파일로 내보낸다. 작업 시트가 밖에서 바뀌면(그리기 도구에서 저장) 1초 안에 다시 읽고, 저장하지 않은 이동이 있으면 다시 읽지 않고 알린다. 최종 파일이 바뀌면 자동 칸과 애니메이션도 1초 안에 새로 읽는다.
- 머리카락 휘기(시트 에디터): 걷기 칸에서 머리는 스마슈처럼 위아래로 움직이므로, 머리카락이 머리보다 한 박자 늦게 따라와야 휘날려 보인다. 에디터의 "머리카락 휘기"는 선택한 칸에서 머리카락(주황·주홍·짙은 갈색 6·7·8번이 120px 이상 이어진 덩어리와 그 테두리. 부츠·땋은 머리 같은 작은 덩어리는 빠짐)을 통째로 휜다. 머리카락 높이의 위 35%는 고정하고, 그 아래는 고정선에서 멀수록 (거리 비율)²만큼 `가로`·`세로` px을 민다. 여기에 가닥 끝이 좌우로 물결치게 `흔들림` px × (거리 비율)² × sin(2π·x/7 + 위상)을 더한다(위상은 걷기 n번째 × 90°라 칸마다 물결이 번갈아 움직임). 그다음 `윤곽` px로 위·옆으로 뻗친 바깥 가닥을 흔든다. 머리카락 덩어리 중심에서 본 각도 a를 따라 접선 방향(정수리는 좌우, 옆은 위아래)으로 `윤곽` × 가중치 × sin(5a + 위상)만큼 밀고, 가중치는 바깥 윤곽에서 1, 안쪽 4px에서 0이다. 바로 아래 4px 안에 얼굴·손·몸이 있는 머리카락(앞머리처럼 얹힌 부분)은 두 단계 모두 움직이지 않는다. 마지막으로 바뀐 픽셀과 그 주변만 두 번 정리한다: 이웃(8방향)에 불투명 픽셀이 하나 이하인 외톨이 머리카락·테두리 픽셀은 지우고, 상하좌우 중 셋 이상이 머리카락·테두리인 빈 픽셀은 머리카락 색(없으면 테두리)으로 메우고, 상하좌우에 같은 색이 없고 셋 이상이 같은 다른 머리카락 색인 점은 그 색으로 바꾸고, 빈 곳과 맞닿은 머리카락 픽셀은 테두리 검정으로 바꾼다(윤곽선이 끊기지 않게). 휜 머리카락은 원래 비어 있던 자리와 머리카락 자리에만 그리고, 머리카락이 비켜난 자리는 바깥과 이어져 있고 옆에 얼굴·손·몸이 없을 때만 비운다. 칸을 고르면 기본값이 채워진다: 세로는 걷기1·3(머리가 올라간 칸) +3, 걷기2·4 −2, 가로는 옆모습이 뒤쪽으로 걷기1·3 3px·걷기2·4 2px, 앞·뒷모습은 걷기1·2 +2·걷기3·4 −2, 흔들림 1.5, 윤곽 1.5. 지금 작업 시트의 걷기 16칸에는 이보다 센 값(세로 +4·−3, 가로 4·3px 또는 ±3, 흔들림 2.5, 윤곽 2)을 적용해 두었다. 바탕을 만드는 기능이라 결과는 손으로 다듬는다. 앞모습은 머리카락 대부분이 얼굴 위에 얹혀 옆머리 끝만 조금 움직인다. 끝부분만 미는 방식을 먼저 해 봤으나 변화가 너무 작아 덩어리 전체를 휘는 방식으로 바꿨다. 계산은 `art/hairLag.ts`의 `bendHair`. 애니메이션 칸은 저장 전 편집 중인 그림을 재생한다(비어 있어 자동으로 채우는 칸만 최종 파일). 그 뒤 칸 전체에서 머리카락 근처만 두 가지를 더 정리한다: 테두리색 픽셀 셋 이상(상하좌우)에 둘러싸인 투명 1픽셀 홈은 테두리색으로 메우고, 바깥과 닿는 2×2 테두리색 블록은 안쪽 한 픽셀을 주변 머리카락 색으로 바꿔 외곽선을 1px로 유지한다.
- 도트 검토 기준(걷기 16칸, 스킬 `pixel-art-craft` 기준): 외곽선 두께 1px 유지(2×2 블록 없음), 윤곽의 1px 홈 없음, 안쪽 검정 점·떨어진 조각 없음, 외곽선 바깥에 비테두리색 없음, 1배·흐리게 본 인상. 손그림 정지 칸의 같은 지표(한 픽셀 점 5, 한 픽셀 고립 7~10 정도)를 걷기 칸의 허용 기준으로 삼았다. 휘기 직후의 두꺼운 윤곽 픽셀은 걷기 16칸 합계 744에서 도구 정리 보강 뒤 182로 줄었고, 이미 휜 작업 시트는 같은 규칙으로 손봐 296px를 바꿨다(정지 칸·스마슈 참고는 그대로). 머리카락 가닥 끝의 거친 윤곽과 땋은 머리 조각은 양식으로 보고 자동으로 건드리지 않았다.
- 팔레트(`KIRI.png`): 0 투명, 1 검정, 2·3 회색, 4 흰색, 5 연노랑, 6 주황, 7 주홍, 8 짙은 갈색, 9 살색, 10 살색 그늘, 11 청록, 12 빨강, 13 짙은 자주, 14 연두, 15 초록.
- 걷기 칸은 방향마다 5칸(위 0·1·2·83·84, 오른쪽 3·4·5·85·86, 아래 6·7·8·87·88, 왼쪽 9·10·11·89·90)이고, 애니 표 각 줄의 0·2·6·10·14번째 값에서 읽는다. 재생 순서는 정지 → 걷기1 → 걷기2 → 정지 → 걷기3 → 걷기4.
- 스마슈 걷기 칸의 규칙(아래 방향에서 확인): 머리·얼굴은 모양이 그대로이고 위아래로만 움직인다(정지 대비 걷기1 −3, 걷기2 +2, 걷기3 −3, 걷기4 +2px, 머리 영역 픽셀 일치가 가장 큰 이동량). 손발만 칸마다 바뀐다. 걷기1·3은 한 손을 머리 옆으로 올리고 다른 손은 크게 앞으로 내리며, 한 발이 칸 아래쪽 가운데로 크게 나온다. 걷기2·4는 올린 손이 귀 높이, 내린 손이 턱 옆이고 발 하나만 보인다.
- 합성: 손그림 정지 칸에서 손(살색·회색·흰색 덩어리)과 발(주황·살색 덩어리)을 떼어 낸 나머지(머리·얼굴·땋은 머리·스카프)를 스마슈와 같은 만큼 위아래로 옮긴다. 손발은 스마슈 걷기 칸에서 테두리로 둘러싸인 덩어리를 테두리째 떼어 와 색만 바꾼다(손: 테두리 → 1, 밝은 털 → 9, 어두운 털 → 10, 회색 → 2, 흰색 → 4. 발: 테두리 → 1, 밝은 털 → 9, 어두운 털 → 6. 손그림 정지 칸의 손발과 스마슈 정지 칸의 손발을 맞대어 정함). 스마슈는 걷기 칸에서 몸통(목깃)이 정지 칸보다 덜 보이므로(아래 방향 정지 4줄, 걷기 1~2줄) 기준 칸이 몸통이 가장 많이 보이는 칸이다. 그래서 걷기 칸에서는 몸통(키리는 연두·초록 스카프와 그 바깥 테두리)을 머리와 따로 다룬다. 위치표의 칸마다 `body`로 정하며, `hide`는 몸통을 그리지 않고(아래 방향 걷기1·3, 스마슈도 목깃이 테두리만 남음), `trim`은 몸통을 머리보다 1줄 위에 놓아 턱 뒤로 한 줄 더 숨기고 양 바깥쪽을 4px(`BODY_TRIM`)씩 깎은 뒤 깎인 끝을 테두리로 막는다(아래 방향 걷기2·4, 스마슈도 목깃이 짧아짐). 그리는 순서는 몸통 → 머리 → 발 → 손이다(손발은 얼굴보다 앞). 합성은 `art/walkFromStand.ts`의 `buildWalk`이고(내보내기 `tools/export.ts`가 부른다), 방향마다 손발이 있는 사각형을 적은 위치표(`TABLES`: 정지 칸의 키리 손·발 상자, 걷기 칸마다 스마슈 손·발 상자)를 쓴다. 상자 안에 통째로 들어가는 덩어리만 손발로 본다. 스마슈 발은 털색 덩어리에서 시작해 같은 상자 안에서 이어진 검은(테두리색) 부분까지 윤곽 전체를 가져온다(검은 밑창도 발이다)(키리 정지 칸은 손이면 살색·회색·흰색, 발이면 주황·살색 덩어리만, 스마슈 걷기 칸은 털·회색·흰색 덩어리만. 뒷모습에서 망토 조각이 상자에 들어오기 때문). 머리 이동량은 스마슈 정지 칸 머리 영역(위 3~33줄, 가로 8~39)의 픽셀 일치가 가장 큰 값(가로 ±2, 세로 ±7)으로 칸마다 구한다. 손발을 자동으로 찾는 방식(스마슈 정지 칸 머리를 걷기 칸에 맞춰 겹쳐 보고 움직인 덩어리를 손발로 보기)도 시험했지만, 고양이 귀처럼 칸마다 모양이 바뀌는 머리 부분을 손으로 잡고 스카프를 손발로 지워서 버렸다.
- 현재 상태: 0·3·6번(위·오른쪽·아래 정지)과 3·4·5·85·86번이 손그림이고, 나머지 위·아래 걷기 칸은 합성 결과를 사용자가 다듬도록 작업 시트에 넣어 두었다. 왼쪽 5칸(9·10·11·89·90)은 오른쪽 5칸을 좌우로 뒤집어 넣었다(스마슈도 왼쪽이 오른쪽의 좌우 반전. `MIRRORS`로 빈 칸을 채움). 땋은 머리처럼 한쪽에만 있는 것은 뒤집으면 반대쪽에 오므로 왼쪽 칸에서 손으로 고친다.
- 오른쪽 스마슈 걷기 칸(4·5·85·86)은 팔다리를 크게 휘두르고 칼 쥔 손이 섞여 있어, 칸 아래쪽(42번째 줄 이하)까지 내려오는 덩어리는 발, 나머지는 손으로 정했다. 걷기1은 앞발을 앞으로 크게 내딛고(오른쪽 아래), 손은 얼굴 앞과 뒤(왼쪽)에 있다. 옆모습은 목깃 보이는 양이 칸마다 일정하지 않아 몸통은 머리와 함께 움직인다(`body: "keep"`).
- 위 방향 스마슈 걷기 칸(1·2·83·84): 걷기1·3은 한 손을 머리 옆(귀 높이 위쪽)으로 올리고 다른 손을 크게 앞으로 내리며 한 발이 칸 아래 가운데로 나오고, 걷기2·4는 올린 손이 귀 옆, 내린 손이 턱 옆이고 발은 칼 뒤로 조금만 보인다. 키리 뒷모습은 머리카락이 넓어 올린 손(걷기1·2의 오른손, 걷기3·4의 왼손)이 머리에 가리므로 위치표에서 뺐다. 내린 손과 발만 가져온다.
- 시도했다가 버린 것: (1) `SMASH.png` 칸에서 머리·손·발을 원·타원·실루엣 윤곽으로 뽑은 스켈레톤 시트. 원·타원은 모양 정보를 잃고, 실루엣 윤곽은 원본을 베낀 것에 가까워 밑그림 구실을 못 했다. (2) 부위를 단순한 입체(타원체·가닥·데칼 등)로 만들어 칸마다 포즈를 잡고 렌더하는 저장소 안 포즈 도구(`?pose=kiri`, `kiri-model.json`, 렌더 결과 `assets/gfx/KIRI_BASE.png`). 입체로는 손그림의 가닥 선과 들쭉날쭉한 머리 윤곽을 만들 수 없었고, 걷기 동작도 손발 화면 위치를 거꾸로 풀어 맞췄지만 스마슈와 맞지 않아 통째로 지웠다.
